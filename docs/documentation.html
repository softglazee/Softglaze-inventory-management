SoftGlaze Stock Manager

A premium Inventory + Point‑of‑Sale system for retail and wholesale shops — one codebase for the browser and the Windows desktop, with first‑class pay‑later (udhaar) credit and rock‑solid double‑entry accounting.

Introduction

Thank you for choosing SoftGlaze Stock Manager. It runs two ways from a single code base:

  • Browser app — host it on your own server / VPS and use it from any device.
  • Windows desktop app — an Electron installer for the shop counter PC.

It is business‑agnostic: choose a Business Type preset and it seeds the right categories, units and sample products. Money is handled as exact decimals and every financial action is a single database transaction, so the books never drift.

Who this is forShop owners and developers deploying a modern POS. Basic familiarity with Node.js and PostgreSQL is enough to self‑host; the desktop build needs no server knowledge for the end user.

Features

POS — full‑screen, keyboard‑first, image tiles, category sidebar, favourites, held bills, quotations.
Payments — cash, split payments, pay‑later (udhaar), change due, receipt print (80mm + A4/PDF).
Inventory — standard / service / combo products, weighted‑average cost, barcodes, multi‑image, low‑stock alerts.
Purchasing — purchases, purchase orders → GRN, returns, landed cost, vendor payables.
Receivables — customer ledgers, credit limits, promises‑to‑pay, cheques, sites/projects.
Money — multiple cash/bank/wallet accounts, transfers, capital & drawings, day close.
Expenses & HR — expenses (incl. recurring), employees, salaries & advances.
Reports — dashboard, P&L, balance sheet, stock valuation, registers — PDF + Excel.
Messaging — WhatsApp (wa.me) & SMTP email receipts/reminders.
Security — roles & permissions, 2FA (TOTP), audit log.
Data — bulk import/export wizard, full JSON backup & restore, optional offsite backup.
UI — warm‑orange design system, light/dark, responsive, animated charts.

Installation (development)

  1. Install dependencies
    npm install
  2. Configure the API — copy the example env and edit it: 
    cp apps/server/.env.example apps/server/.env
    Set DATABASE_URL and strong JWT_SECRET / JWT_REFRESH_SECRET values.
  3. Create the schema & seed defaults
    npm run db:migrate
npm run db:seed
  4. Run it (web on 5173, API on 4000)
    npm run dev
  5. Open http://localhost:5173.
No PostgreSQL yet? The quickest option is Docker (docker run -e POSTGRES_PASSWORD=… -p 5432:5432 postgres) or install PostgreSQL directly and create a database named softglaze.

First run & business types

On a fresh install the app detects that no owner exists and shows Register. The first account you create becomes the Super Admin / owner; public registration then closes and further staff are created under Users & Roles.

The owner is guided through onboarding to pick a Business Type. You can change or re‑apply it any time under Settings → Business Type — it adds starter categories, units and sample products and never deletes your data.

Point of sale

Open Sell → POS / New Sale for a full‑screen till.

  • Search products by name / SKU / barcode (F2), or tap the image tiles; use the category sidebar and favourites to browse fast.
  • Pick a customer (or leave Walk‑in); add one on the fly. Contract rates and price groups auto‑apply.
  • Take cash, split across accounts, or leave a balance as udhaar (pay‑later) — respecting the customer's credit limit.
  • Hold a bill, save a Quotation, or Complete and print (80mm thermal or A4 / PDF).
Shortcuts F2 search · F9 payment · F10 complete · Esc void line.

Inventory

  • Products — grid or table view, KPI cards, images, prices, live stock badges. Types: standard (tracks stock), service (no stock), combo (bundle that deducts components).
  • Stock — adjustments with categorised reasons (breakage, theft, count correction…), which feed the shrinkage report.
  • Purchases & Purchase Orders — receive stock (weighted‑average cost auto‑updates), record vendor bills and returns; POs partially receive into GRNs.
  • Weight Calc / Cutting — for steel sold by weight (rods/sheets) and bar cutting jobs.
  • Categories / Brands / Units — full CRUD with images.

Customers & vendors

  • Customers — ledgers, opening balances, credit limits, sites/projects, price groups, loyalty points, statements.
  • Vendors — payables, opening balances, debit/credit notes.
  • Promises & cheques — track promises‑to‑pay and post‑dated cheques through clearing/bounce.

Money & reports

  • Accounts & cash — cash drawer, bank and wallet accounts; transfers, capital & drawings, day close, bank reconciliation.
  • Payments & expenses — receive/pay against ledgers; expenses including recurring monthly costs.
  • Reports — dashboard, accrual Profit & Loss, balance sheet, stock valuation, sales & purchase registers, comparative (MoM/YoY). Every report exports to PDF and Excel.

Settings & users

  • Shop Profile — name, logo & favicon (drag‑drop), contact, tax numbers, invoice header/footer, receipt size, rounding, loyalty.
  • Business Type — apply presets.
  • Roles & Permissions — data‑driven matrix per role; the server enforces every permission.
  • Integrations — WhatsApp mode & templates, SMTP email, SMS gateway, offsite cloud backup.
  • Security — enable 2FA (TOTP). Audit Log — every important action, filterable.
  • Users & Roles — create staff, set roles & commission, reset passwords. Each user can set their own name, phone, password and profile picture from the account menu.

Production & hosting

  1. Build both apps:
    npm run build
  2. Single‑origin mode — set SERVE_WEB=1 and NODE_ENV=production so the API also serves the built web app (/api and /uploads stay untouched).
  3. Run the API with a process manager (PM2) behind Nginx with HTTPS; point DATABASE_URL at your production PostgreSQL.

A detailed VPS walkthrough (Nginx + PM2 + Postgres, backups, TLS) is in docs/07-DEPLOYMENT.md.

Desktop installer (Windows) — fully offline

The apps/desktop workspace packages the built API + web and a bundled PostgreSQL into one installable Windows app. The shop PC needs no separate database and no internet. On first launch the app creates a private database under %APPDATA%/SoftGlaze/pgdata, applies all migrations, seeds the shop defaults, and opens the shop — a splash screen shows while that ~1‑minute first‑run setup happens. Uploads are stored under %APPDATA%/SoftGlaze/uploads.

  1. From apps/desktop, build the installer: 
    cd apps/desktop
npm run dist
    This generates the Prisma client, builds the server + web, stages a minimal PostgreSQL runtime (~120 MB) into vendor/pgsql, then bundles everything with electron‑builder.
  2. The generated release/SoftGlaze-Stock-Manager-Setup-x.x.x.exe installs the app (per‑user; the install folder can be changed).
  3. Launch SoftGlaze Stock Manager, register the owner account, pick a business type, and start selling — everything runs locally.
Bundled PostgreSQL source. The build copies a minimal PostgreSQL 16 runtime from ../pg/pgsql (or the folder in the SOFTGLAZE_PG_DIR environment variable — any PostgreSQL 16 for Windows install works). Stop the dev API server before building so Windows doesn't lock the Prisma engine DLL.
External database instead? Edit %APPDATA%/SoftGlaze/softglaze.config.json and set "embeddedDb": false with a "databaseUrl" to point the desktop app at your own PostgreSQL.

Backup & restore

Settings → Backup downloads a full portable JSON snapshot of everything — products, sales, customers, money, settings. Restore wipes and reloads from a snapshot in one transaction (you may need to sign in again afterward). You can also enable a nightly upload to a pre‑signed S3 / Google Cloud URL under Settings → Integrations.

Restore replaces everythingOnly restore to recover — it wipes the current data before loading the backup.

Accounting integrity

Financial correctness is guaranteed by design:

  • Money is an exact Decimal; every financial write is one atomic transaction.
  • Stock (StockMovement) and money (AccountEntry) ledgers are the source of truth; cached balances are updated in the same transaction.
  • Documents are never hard‑deleted (cancel / return instead).
  • GET /reports/integrity verifies caches, per‑document totals, customer/vendor reconciliation and that Assets = Liabilities + Equity — it should always be all‑green.

Updating

  1. Back up first (Settings → Backup, and/or a database dump).
  2. Replace the source with the new version, keeping your .env and uploads/.
  3. Install & migrate:
    npm install
npm run db:migrate
npm run build
  4. Restart the API (and rebuild the desktop installer if you distribute it).
