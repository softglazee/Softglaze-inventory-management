SoftGlaze Stock Manager

A premium Inventory + Point-of-Sale system for retail and wholesale shops. One code base ships to both the browser and the Windows desktop, with first-class pay-later (udhaar) credit and exact, ledger-backed accounting.

Introduction

Thank you for choosing SoftGlaze Stock Manager. It runs two ways from a single code base, and you can switch between them (or run both against the same database) at any time.

Windows desktop

One installer for the shop counter PC. Bundles its own PostgreSQL — no database to install, no internet needed. Best for a single shop.

Browser / self-host

Host it on your own VPS and reach it from any phone, tablet or PC. Best for multiple users, multiple locations, or remote access.

The app is business-agnostic. On first run you pick a Business Type preset and it seeds the right categories and units for your trade. Money is stored as exact decimals (never floating point), and every financial action is written in a single database transaction — so the books never drift.

Always-current version online This guide is also published at softglaze.com/docs/stock-manager. If you are reading a copy that shipped with an older download, check there for the latest.
Who this guide is for Shop owners setting up the desktop app need only the Windows desktop section. Developers self-hosting the browser app should read Server / VPS install — basic familiarity with Node.js, nginx and PostgreSQL is enough.

Feature overview

Point of sale

Full-screen, keyboard-first POS with product tiles, barcode search, held bills, quotations, split payments, cash or udhaar, and 80mm / A4 receipts.

Inventory

Standard, service and combo products; weighted-average cost; barcodes; multiple images; low-stock alerts; adjustments with reasons; purchase orders → GRN.

Receivables & payables

Customer and vendor ledgers, credit limits, promises-to-pay, post-dated cheques, customer sites/projects, price groups and contract rates.

Money

Multiple cash / bank / wallet accounts, transfers, capital & drawings, day close, expenses (including recurring), employee salaries and advances.

Reports

Dashboard, accrual P&L, balance sheet, stock valuation, sales / purchase registers and comparative reports — each with an on-screen table plus PDF and Excel export.

Security

JWT access + rotating refresh tokens, bcrypt(12), optional 2FA (TOTP), a dynamic role permission matrix, rate-limited auth, and a full audit log.

Backup

One-click portable JSON snapshot and restore, plus optional nightly offsite upload to a pre-signed S3 / GCS URL.

Extras

WhatsApp (wa.me) and SMTP messaging, loyalty points, bulk import/export wizard, built-in calculator, construction estimator, steel weight calculator.

Local install (development)

Use this to run the source on your own machine — for evaluation, customisation, or before deploying to a server.

  1. Install dependencies From the project root (the folder containing the top-level package.json): 
    npm install

    This installs all three workspaces (apps/server, apps/web, apps/desktop) in one go.

  2. Create the database Create an empty PostgreSQL database and a user that owns it: 
    # psql as a superuser
CREATE USER softglaze WITH PASSWORD 'choose_a_password';
CREATE DATABASE softglaze OWNER softglaze;

    A docker-compose.yml is included if you would rather run PostgreSQL in Docker.

  3. Configure the API Copy the example environment file and edit it: 
    cp apps/server/.env.example apps/server/.env

    Set DATABASE_URL to match the user and database you just created, and generate two different secrets for JWT_SECRET and JWT_REFRESH_SECRET. See Configuration for every key.

  4. Create the schema and seed defaults 
    npm run db:migrate
npm run db:seed

    Seeding creates units, categories, payment methods, expense categories, settings and the role permission matrix. It does not create a user — you do that in the browser.

  5. Start the app 
    npm run dev

    This runs the API on http://localhost:4000 and the web app on http://localhost:5173 together, both with hot reload. Open the web address.

  6. Create the owner account The app detects that no user exists and offers Create owner account. The first account becomes the Super Admin; registration then closes permanently. Continue at First run.

Server / VPS install (production)

This puts the browser app online with HTTPS, a process manager that restarts it automatically, and nightly backups. The walkthrough targets Ubuntu 22.04 / 24.04; a 2 GB VPS is plenty.

Before you start You need SSH access to the server, and a domain or sub-domain (e.g. stock.yourshop.com) with an A record pointing at the server's IP address.
  1. Install the system packages — as root: 
    apt update && apt upgrade -y
apt install -y nginx postgresql ufw git
curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && apt install -y nodejs
npm i -g pm2
ufw allow OpenSSH && ufw allow 'Nginx Full' && ufw enable
  2. Create the database 
    sudo -u postgres psql -c "CREATE USER softglaze WITH PASSWORD 'STRONG_DB_PASSWORD';"
sudo -u postgres psql -c "CREATE DATABASE softglaze OWNER softglaze;"

    Use a long random password — you will paste it into DATABASE_URL next.

  3. Deploy the application 
    mkdir -p /var/www && cd /var/www
git clone <YOUR_REPO_URL> softglaze && cd softglaze
bash deploy/deploy.sh

    The first run stops and asks you to create apps/server/.env. Copy deploy/env.production.example to apps/server/.env and fill in:

    • the real DATABASE_URL password;
    • two different secrets, each from openssl rand -hex 32;
    • CORS_ORIGIN=https://stock.yourshop.com;
    • UPLOAD_DIR as an absolute path outside the checkout, e.g. /var/www/softglaze-uploads, so images survive redeploys.

    Then run bash deploy/deploy.sh again. It installs, builds, migrates, seeds and starts the API under PM2.

  4. Configure nginx 
    sudo cp deploy/nginx-softglaze.conf /etc/nginx/sites-available/softglaze
sudo sed -i 's/stock.YOURSHOP.com/stock.yourshop.com/' /etc/nginx/sites-available/softglaze
sudo ln -s /etc/nginx/sites-available/softglaze /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx

    nginx serves the built web app and proxies /api and /uploads to the Node process.

  5. Enable HTTPS — free, and renews itself: 
    sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d stock.yourshop.com
  6. Schedule nightly backups — 3 AM every day: 
    ( crontab -l 2>/dev/null; echo "0 3 * * * cd /var/www/softglaze && bash deploy/backup.sh >> /var/log/softglaze-backup.log 2>&1" ) | crontab -

    deploy/backup.sh runs pg_dump and prunes old dumps.

  7. Open the site and register Visit https://stock.yourshop.com, create the owner account, choose your business type, and you are live.

Single-origin mode (no nginx)

The API can serve the built web app itself, which is handy for a quick internal deployment. Set SERVE_WEB=1 and NODE_ENV=production, run npm run build, then start the server — it serves the SPA with correct fallback while leaving /api and /uploads untouched.

Never commit secrets apps/server/.env and the uploads folder must stay out of version control. Both are already listed in .gitignore.

Windows desktop app

The desktop build wraps the API, the web app and a private PostgreSQL into a single Windows installer. The shop PC needs no database, no Node.js and no internet connection.

Installing (for the shop)

  1. Run the installer Double-click SoftGlaze-Stock-Manager-Setup-1.0.0.exe and follow the prompts. You can change the install folder; a desktop and Start-menu shortcut are created.

    Windows SmartScreen may warn that the publisher is unknown because the build is not code-signed. Choose More info → Run anyway.

  2. First launch A splash screen appears while the app creates its private database, applies migrations and seeds defaults. This takes up to a minute the first time — later launches are quick.
  3. Create the owner account The window opens on the registration page. Create the owner account, pick a business type, and start selling. See First run.

Using an external PostgreSQL instead

Edit softglaze.config.json, set "embeddedDb": false and provide your own databaseUrl. The app then stops managing PostgreSQL and simply connects.

{
  "embeddedDb": false,
  "databaseUrl": "postgresql://user:pass@192.168.1.10:5432/softglaze?schema=public"
}

This is how you point several counter PCs at one shared shop database.

Ports

The app serves itself on port 4000 by default. If that port is already taken it automatically moves to the next free one (4001, 4002, …) and logs the choice to desktop.log, so it never collides with a development server or a second copy. The bundled PostgreSQL listens on 127.0.0.1:55432 only — it is never exposed to the network.

Building the installer yourself

cd apps/desktop
npm run dist

The predist step generates the Prisma client, builds the server and web app, and stages a minimal PostgreSQL runtime. The finished installer appears in apps/desktop/release/. Anything placed in apps/server/uploads/ before the build is bundled and restored into the user's uploads folder on first launch — that is how a data-preloaded build ships its product photos.

Dashboard

The landing screen answers "how is the shop doing?" at a glance. Everything respects the signed-in user's role — a cashier never sees profit figures.

  • Headline cards — total sales, sales returns, total purchases and purchase returns for the month.
  • Money cards — profit (or today's sales for restricted roles), invoice due from customers, expenses and payables to vendors.
  • Sales & Purchase chart — a daily comparison over the range you select (today, 7, 14 or 30 days).
  • Overall information — supplier, customer and order counts, plus first-time vs returning customers.
  • Lists — top selling products, low stock, recent sales and recent transactions.
  • Sales statistics — revenue against expense over the last twelve months.
  • Order statistics — a weekday × hour heatmap showing when your shop is busiest.
Low stock banner When any product falls to or below its minimum level, a banner appears at the top with a direct link to restock.

Point of sale

The POS is a full-screen, keyboard-first billing screen built for speed at a busy counter.

Making a sale

  1. Add items Search by name, SKU or barcode, or click a product tile. A barcode scanner types into the search box and Enter adds the first match.
  2. Adjust the line Change quantity, override the price (if your role allows) or apply a line discount.
  3. Choose the customer Walk-in by default, or search an existing customer — you can add a new one without leaving the screen.
  4. Take payment Cash, bank, card, mobile wallet, credit (udhaar), or a split across several methods. Credit sales are blocked when the customer is over their limit.
  5. Complete and print The invoice saves in one atomic transaction and prints an 80mm thermal receipt or an A4 PDF.

Held bills and quotations

Inventory & stock

Products

  • Types — Standard (stocked), Service (no stock, e.g. delivery or cutting charges) and Combo (a bundle of other products).
  • Identity — auto-generated SKU, barcode, brand, category and unit.
  • Pricing — cost, retail and wholesale prices, tax rate, and optional price groups or contract rates for specific customers.
  • Images — several per product with one marked primary; thumbnails are generated automatically.
  • Alerts — a minimum stock level drives the low-stock badge, dashboard banner and report.

How stock is tracked

Every movement — a sale, a purchase, a return, an adjustment — writes a row to the stock ledger. The quantity shown on a product is a cache updated inside the same transaction, so the two can never disagree. This gives you complete traceability: you can always see exactly why a number changed.

Purchase OrdersRaise a PO to a vendor, then receive it into stock (GRN)

Costing

Cost is weighted average, recalculated on every purchase:

newAverage = (oldQty × oldAverage + inQty × inCost) ÷ (oldQty + inQty)

Each sale line stores a snapshot of the cost at that moment, so profit on an old invoice never changes when prices move later.

Purchases

Recording a purchase does four things in one transaction: stock comes in, the weighted-average cost is recalculated, the vendor payable increases, and any payment you make is recorded.

  1. Pick the vendor and the purchase date and reference.
  2. Add items with quantity and cost price.
  3. Add charges such as freight or loading — these are spread across the items so your landed cost stays accurate.
  4. Pay now or later — pay in full, part-pay, or leave the whole amount on the vendor's account.

Purchase returns are raised against the original bill: stock goes out and the payable reduces. Vendor notes record debit and credit notes outside a specific bill. Foreign-currency purchases are converted to your currency on entry so all downstream reporting stays in one currency.

Customers & vendors

Ledgers

Every customer and vendor has a running ledger: each invoice, return and payment with a balance after every line. Print or share it as a PDF statement — useful when settling a monthly account.

Credit control

  • Credit limits — POS blocks a credit sale that would exceed the limit; an administrator can override.
  • Receivables aging — outstanding balances bucketed 0–30, 31–60, 61–90 and 90+ days.
  • Promises to pay — record what a customer committed to and follow it up.
  • Post-dated cheques — a register of cheques with due dates and clearing status.

Extras

  • Customer sites — separate sub-ledgers per project or delivery site for the same customer.
  • Price groups and rate contracts — agreed pricing that applies automatically at POS.
  • Outreach — send statements or reminders in bulk over WhatsApp or email.

Forgotten passwords

There are two independent routes back in, so a shop can never be locked out.

  1. Email a reset link Click Forgot password? on the sign-in screen and enter your address. The link lasts one hour, works once, and signs the account out everywhere when used.

    This needs email to be configured (Settings → Integrations). An offline desktop install has no mail server, so use the second route there.

  2. An administrator resets it From Users & Roles, open the user and set a new password. Always available, no email required. Keep at least two administrator accounts so someone can always do this.
The reset page never says whether an address has an account It gives the same answer either way, so it cannot be used to discover who works at the shop.

Two-factor authentication

Any user can enable TOTP two-factor authentication under Settings → Security. Scan the QR code (or type the secret) into an authenticator app; from then on sign-in asks for the six-digit code. Disabling it requires the account password.

Forgotten passwords

There is no email reset by design — a shop should not depend on a mail server. An administrator resets a staff password from the Users screen. Keep at least two administrator accounts so you are never locked out.

Pictures

Images are managed inside the app; nothing needs to be uploaded to the server by hand.

  • Shop logo — Settings → Shop. Appears on invoices, receipts, PDF reports and the sign-in screen. It can be replaced or removed at any time.
  • Product photos — open a product and drag images onto the box, or click to browse. Up to five per product. Click one to make it the primary picture (the one shown in POS and lists), or delete it with the bin icon. Deleting the primary promotes the next image automatically.
  • Category pictures — set on the category, used for the POS tiles.
  • Profile pictures — each user sets their own under My account.
Images are files, not database rows The database stores the path to each picture; the files live in your uploads folder. Back up both together, or restored products will show placeholder icons. See Backup & restore.

Backup & restore

In the app

Settings → Backup downloads a complete portable JSON snapshot of your shop. Restoring one wipes the current data and reloads the snapshot in foreign-key order inside a single transaction — so a failed restore leaves nothing half-applied.

Restore replaces everything Take a fresh backup immediately before restoring an older one. There is no undo.

On a server

deploy/backup.sh runs pg_dump and prunes old dumps; the install steps schedule it nightly at 3 AM. Copy the dumps off the server regularly — a backup that lives only on the machine it protects is not a backup.

# restore a dump into an empty database
psql -U softglaze -d softglaze -f softglaze-2026-08-06.sql

On the desktop

Close the app and copy %APPDATA%\@softglaze\desktop — that folder holds the database, uploaded images and configuration. Restore by copying it back.

Images live outside the database A JSON snapshot or SQL dump records the paths of product photos, not the files. Always back up your uploads folder alongside the database, or restored products will show placeholder icons.

Updating

Server

cd /var/www/softglaze
bash deploy/update.sh

The script backs up the database first, then pulls, installs, builds, applies any new migrations and restarts the process under PM2.

Desktop

Run the newer installer over the existing installation. Your database, images and settings live in %APPDATA% and are untouched; migrations are applied automatically on the next launch.

Take a backup first Migrations are one-way. A snapshot before updating costs seconds and saves afternoons.

Accounting integrity

The books are designed so they cannot quietly drift:

  • Money is an exact decimal everywhere — never a floating-point number. Quantities carry three decimal places, money two, and rounding happens only at the edges.
  • Every financial write is one database transaction. A sale creates the invoice, its lines, the stock movements, the payments, the balance updates and the audit entry together, or not at all.
  • The stock and account ledgers are the source of truth. The quantity on a product and the balance on an account are caches, updated in that same transaction.
  • Financial documents are never hard-deleted. They are cancelled, or reversed with a return.
  • Each sale line stores the cost at the time of sale, so historic profit never changes when prices move.

The integrity check

Administrators can run a built-in verification that proves the books balance. It confirms that ledger sums match cached balances, that every document's totals add up, that customer and vendor balances reconcile with their ledgers, and that assets = liabilities + equity.

GET /api/v1/reports/integrity

An all-green result means every figure in every report is internally consistent.

Troubleshooting

The desktop app shows an error about the background service

Open %APPDATA%\@softglaze\desktop\desktop.log — it records the whole startup sequence and is rewritten on every launch. The last lines almost always name the cause.

"Wrong email or password" when the password is right

Check the account is still enabled — a disabled account reports "This account is disabled". If you have genuinely lost the only administrator password, another administrator must reset it from the Users screen.

Sign-in says "Server did not respond correctly"

The web app reached something that was not the API. Usually the API is not running, or the database behind it is down. Check /api/v1/health, then confirm PostgreSQL is up and DATABASE_URL is correct.

Too many sign-in attempts

Authentication endpoints are rate-limited to protect against brute force. Wait fifteen minutes, or restart the API to clear the counter during development.

Product images show a placeholder icon

The database stores image paths; the files themselves live in your uploads folder. If that folder was moved, emptied or left out of a restore, the paths no longer resolve. Restore the folder from a backup, or re-upload the images. Confirm UPLOAD_DIR points where the files actually are.

Port already in use

The desktop app moves to the next free port automatically. The development server does not — stop whatever else is on port 4000, or change PORT in apps/server/.env.

Running both at once The desktop app and npm run dev both want port 4000. Either close one, or give the development API a different PORT.

Windows SmartScreen blocks the installer

The build is not code-signed. Choose More info → Run anyway. Buying a code-signing certificate removes the warning.

Reports do not match what I expect

Run the integrity check first. If it is all green, the figures are internally consistent and the difference is usually a date range, a cancelled document, or the accrual-versus-cash distinction described under Money & accounts.

Changelog

1.0.1

Stability release. Every item below was reproduced, fixed and re-tested.

  • Blank window after creating the owner account. On a brand-new installation the app unmounted itself the moment the one-time setup screen should have appeared, leaving an empty window and no way in. Affected every fresh install.
  • Signed out on every reload. Restoring a session discarded a perfectly valid seven-day sign-in token, so reloading the page more than fifteen minutes after signing in sent you back to the login screen. Sessions now last as designed.
  • Desktop app could open onto the wrong server. It assumed port 4000 was free; if anything else held it, the window loaded that other program instead of the shop. It now claims a free port at startup and records which one in its log.
  • Confusing message after too many sign-in attempts. The rate limiter replied in a format the app could not read, so it reported that the server was broken. It now says plainly that you should wait a few minutes.
  • Product images can now ship with a data-preloaded build and are restored on first launch.
  • Added an automated check that prevents the class of defect behind the blank-window bug from ever reaching a release again.

New in 1.0.1

  • Keep me signed in. A choice on the sign-in screen: stay signed in for up to seven days on your own machine, or end the session the moment the window closes on a shared one.
  • Forgot password. Request an emailed reset link that lasts an hour and works once. Where email isn't configured — an offline desktop shop, for instance — the page says so and points to an administrator, who can still reset it from Users & Roles.

1.0.0

Initial release — POS and sales, inventory and purchasing, customer and vendor ledgers with credit control, accounts and expenses, payroll, the full report suite with PDF and Excel export, role permissions, two-factor authentication, backup and restore, business-type presets, and both the browser and Windows desktop targets.
